# Horror Movie Madness — party site

A one-page invite + RSVP/potluck sign-up, hosted free on GitHub Pages.
RSVPs are stored in a Google Sheet you own (via a tiny Google Apps Script).

> **Status:** the party was 2026-10-24. GitHub Pages was turned off on 2026-10-26, so the
> site is offline; this repo is kept as the template for future years. See
> [Reusing for a new year](#reusing-for-a-new-year).

```
index.html          the page
styles.css          the look
app.js              loads/saves RSVPs, renders the feast + body count
config.js           ← the file you edit (sheet URL, invited/expected counts)
apps-script/Code.gs ← paste into Google Apps Script (not used by the site itself)
```

Until `sheetUrl` is filled in, the page runs in **demo mode** with sample entries,
so you can open `index.html` locally and see it right away.

---

## 1. Hook up the Google Sheet (≈5 min)

1. Create a new Google Sheet (name it whatever, e.g. *Halloween 2026 RSVPs*).
2. In the sheet: **Extensions → Apps Script**.
3. Delete the starter code, paste in everything from `apps-script/Code.gs`, click **Save**.
4. **Deploy → New deployment** → gear icon → **Web app**.
   - *Execute as:* **Me**
   - *Who has access:* **Anyone**
5. Click **Deploy**, approve the permissions prompt (Google will warn that the app
   is unverified — it's your own script; choose *Advanced → Go to … (unsafe)*).
6. Copy the **Web app URL** (ends in `/exec`) and paste it into `config.js`:
   ```js
   sheetUrl: "https://script.google.com/macros/s/XXXXXXXX/exec",
   ```

An **RSVPs** tab is created automatically on the first submission.

7. **Fast loading (recommended):** in the script editor, pick **setUp** in the function
   dropdown and click **Run** (approve the permission prompt). This creates a **Public**
   tab holding only name, guests, attending, category and dish — no timestamps or notes —
   and makes your hand edits refresh the site's cached list.
8. In the Sheet: **File → Share → Publish to web** → choose the **Public** tab (not
   "Entire document") and **Comma-separated values (.csv)** → **Publish**. Paste that link
   into `publicCsvUrl` in `config.js`. The site then loads in about a second; the
   published copy lags the Sheet by a few minutes.

**The RSVP Sheet (hosts only):**
https://docs.google.com/spreadsheets/d/19wzK4NIQ8-_M5SEQ6O7gRTEMIPiytafQsrsuraA0W04/edit
Make all edits on the **RSVPs** tab. The **Public** tab is generated by a formula and
can't be edited directly; it (and the site) update from RSVPs within a few minutes.

**Managing entries:** edit or delete rows right in the sheet. To hide a row from the
website without deleting it, type anything in its **Hide** column. The
*Note to hosts* column is never shown on the site.

> If you ever edit `Code.gs`, use **Deploy → Manage deployments → ✏️ → Version: New version**
> so the URL stays the same.

## 2. Publish on GitHub Pages

1. Create a new **public** repository on GitHub (e.g. `halloween-party`).
2. Upload the contents of this `party-site` folder (drag-and-drop on the repo page works,
   or use git — see below).
3. Repo **Settings → Pages** → *Source:* **Deploy from a branch** → *Branch:* `main` / `(root)` → **Save**.
4. After a minute, your site is live at `https://<your-username>.github.io/halloween-party/`.
   Put that link (or a QR code of it) where the invite says *RSVP page link*.

With git:

```bash
cd party-site
git init
git add .
git commit -m "Halloween party site"
git branch -M main
git remote add origin https://github.com/<your-username>/halloween-party.git
git push -u origin main
```

> Only push the `party-site` folder — keep the planning spreadsheets out of the repo.

## 3. Updating the Body Count

Open `config.js`, change `invited`, `expected`, and `lastUpdated`, then commit & push
(or edit the file directly on github.com with the ✏️ pencil icon). "Souls confirmed"
and the countdown update themselves from the RSVPs and the date.

## How it works

- **RSVP form** → POST to the Apps Script web app (`sheetUrl` in `config.js`) → appends a
  row to the **RSVPs** tab. The script replies with the updated list.
- **Guest list** → read from the published **Public** tab as CSV (`publicCsvUrl`):
  about half a second, but it lags the Sheet by a few minutes. For 10 minutes after a
  browser submits an RSVP, that browser reads the slower, always-current script instead
  so the new entry doesn't vanish. The last list seen is cached in localStorage and shown
  instantly on the next visit.
- Apps Script is slow and flaky (1–77 s per request, sometimes saves the row but returns
  an empty reply). So POSTs time out after 120 s, and a failed POST re-checks the list
  before showing an error.
- RSVPs tab columns: Timestamp | Name | Guests | Attending | Category | Item | Note to
  hosts | Hide. The Public tab is the formula
  `=IFERROR(FILTER(RSVPs!B2:F, RSVPs!B2:B<>"", RSVPs!H2:H=""), "")`, created by
  `setUp()`; it can't be edited by hand.
- **Body Count**: `invited`, `expected` and `lastUpdated` are hand-edited in `config.js`;
  "souls confirmed" counts Yes RSVPs. `partyStart` drives the countdown, `rsvpBy` the
  deadline.
- After changing `styles.css` or `app.js`, bump the `?v=N` cache-buster on the asset URLs
  in `index.html` (last used: `v=14`), or browsers keep the old files. Pages updates
  40–100 s after a push.
- `SHEET_ID` in the repo copy of `Code.gs` is blank on purpose (keeps the Sheet ID out of
  this public repo). Re-enter it when pasting into Apps Script. It must come from a
  `/spreadsheets/d/…` URL, not a Google **Form** URL.
- In `app.js`, form fields are read with `form.elements.namedItem(...)`:
  `form.elements.item` is a built-in method, not the field named "item".

## Reusing for a new year

1. Copy this folder (without `.git`) to a new folder and create a new public repo for
   it (e.g. `halloween-2027`). Keep this repo as the 2026 record.
2. Re-theme: invite copy and section text are in `index.html`; colors, fonts and the
   moon/bat/tree art are in `styles.css` and the inline SVG in `index.html`. Update the
   page `<title>`, the `description`/`og:` meta tags (they set the link preview in
   texts), and the "Horror Movie Madness" header comment in `Code.gs`.
3. Make a fresh Google Sheet and follow section 1 above (new Apps Script project, run
   `setUp`, publish the Public tab). Put the new `sheetUrl` and `publicCsvUrl` in
   `config.js`, along with the new `partyStart`, `rsvpBy` and Body Count numbers.
4. Leaving `sheetUrl` blank runs the page in demo mode with sample entries, which is handy
   while re-theming.
5. Publish (section 2), submit one clearly labeled test RSVP, check it appears, delete
   it from the Sheet.
6. After the party: turn off Pages (Settings → Pages), stop publishing the Public tab,
   and archive the Apps Script deployment.

## Notes

- The Apps Script URL is visible in the page source — anyone with the link could
  submit an entry, which is the point. The hidden honeypot field filters basic bots;
  use the **Hide** column for anything silly.
- Guest names and dishes are public to anyone with the page link. Private notes stay in the sheet.
